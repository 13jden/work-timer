## 1. 背景

池机制是 v2.0 PRD 最有价值也最复杂的功能：把「周期性/押金性」的钱抽象成**池**，每日生成**虚拟**预扣/预加记录，实际发生时通过**认领**关联确认。

> ⚠️ 边界 case 多（跨月、逾期、部分认领、删除回滚），需要大量单测覆盖。

## 3. 关键设计点（开发前细化）

- **虚拟记录生成时机**：池创建/周期滚动时批量生成 `poolStatus='virtual'` 的 `AccountRecord`，还是统计时动态计算？（倾向后者，避免数据膨胀，开发前定稿）
- **认领**：实际记录（如交房租）关联 `poolId + poolDirection`，对应虚拟记录转 `confirmed`
- **逾期**：周期结束未认领完 → 状态 `overdue`，剩余虚拟记录处理策略待定
- **删除回滚**：删除已认领记录 → 虚拟记录回退为未确认
