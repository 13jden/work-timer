## 1. 背景

池机制是 v2.0 PRD 最有价值也最复杂的功能：把「周期性/押金性」的钱抽象成**池**，每日生成**虚拟**预扣/预加记录，实际发生时通过**认领**关联确认。

> ⚠️ 边界 case 多（跨月、逾期、部分认领、删除回滚），需要大量单测覆盖。

## 3. 详细设计（2026-09-04 定稿）

### 3.1 虚拟记录生成时机：**预生成**（定稿，放弃动态计算）

池创建 / 周期滚动时，批量生成 `poolStatus='virtual'` 的真实 `AccountRecord`，同时写入 `PoolCycle.transactions`。

**理由**：
1. `AccountRecord` 已有 `poolId / poolDirection / poolStatus` 字段，`stats.ts` 已按 `poolStatus='virtual'` 过滤（TASK-038 预留开关），预生成与既有架构完全对齐；
2. 验收标准明确「每日虚拟记录生成」，预生成使统计/日历打开虚拟开关后自然可见；
3. 数据量可控：每池每日最多 1 条虚拟记录，数年量级无压力；
4. 认领/回滚只需更新记录字段，无需在统计层做复杂的动态合并。

### 3.2 均摊型池（equalize）

- **语义**：周期性支出（房租/会员费）。如 ¥3000/月 → 每日虚拟预扣 ¥100（`type='expense'`，`amount=-dailyVirtual`）。
- **周期**：每自然月一个 `PoolCycle`（`monthKey`）。建池时生成当月 + 未来共 `cycleMonths` 个周期；跨月滚动由应用启动时的 `syncCycles` 补齐。
- **每日分配**：周期内每天一条虚拟记录（`dateKey` 逐日），`dailyVirtual = totalAmount / dayCount`（保留 2 位小数，尾差补到最后一天）。
- **`dayRange`**：可选，限定每月生效日期区间（如 10 号～次月 9 号简化为当月 dayRange 内的天数）；未配置则整月。

### 3.3 认领机制（claim）

- 添加实际记录时可选「关联池」：选池 + 方向。
- **匹配规则**：按周期内**未确认**虚拟交易的时间顺序贪心匹配：
  - 交易金额 ≤ 剩余认领额 → 整笔确认（`transaction.recordId = 实际记录 id`，虚拟记录 `poolStatus='confirmed'`）；
  - 下一笔交易金额 > 剩余认领额 → **拆分**该交易：确认部分（金额 = 剩余）+ 保留部分（金额 = 差额，仍 virtual）；
  - 认领额用尽即停止，未匹配完的实际金额正常记账、不挂池。
- **方向语义**：
  - 均摊型认领实际支出 → `poolDirection='out'`（预扣兑现为真实支出）；
  - 存池型存入 → `poolDirection='in'`；取出 → `poolDirection='out'`。
- **周期状态**：全部交易确认 → `confirmed`；存在未确认 → 保持 `generating`。

### 3.4 存池型池（deposit）

- **语义**：押金。存入时真实支出挂池（`in`），退回时真实收入挂池（`out`）。
- **不生成虚拟记录、不关联天数**；用一个建池当月的常驻 `PoolCycle` 承载 transactions。
- **池余额** = Σ(in 已确认) − Σ(out 已确认)。

### 3.5 逾期与回滚

- **逾期扫描**（应用启动时）：`monthKey < 当前月` 且 `status='generating'` 的均摊型周期 → `overdue`。剩余虚拟记录保留 `virtual`（统计默认排除），展示层标灰。
- **删除回滚**：删除已认领的实际记录 → 关联交易清除 `recordId` 回退 `virtual`（拆分产生的确认部分合并回原交易金额逻辑：确认部分回退、保留部分不动），周期状态回退 `generating`。
