## Phase 1 · 数据层与基础框架

**目标**：跑通数据模型和 store，为 UI 层铺路

- 设计数据结构：`AccountRecord` / `Category` / `Folder` / `Account` / `PoolConfig` / `PoolCycle` / `PoolTransaction`
- Zustand store 搭建（`useAccountStore`），分模块组织
- localStorage 持久化 + 数据迁移钩子
- 基础 CRUD 方法 + 单测（`src/lib/accounting/`）
- 与现有 timer store 的边界隔离

**验收**：store 能 CRUD，单测通过

---

## Phase 2 · 记账核心：记录 + 分类

**目标**：能记账、能分类、能看列表 —— 最基础闭环

- 快速记录（一行输入 + 按钮）
- 完整添加弹窗（底部半屏模态框）
- 分类文件夹（新建 / 删除 / 长按拖动排序）
- 未分类区域（有则显示，无则隐藏）
- 首页今日记录列表
- 记录编辑 / 删除

**验收**：能在浏览器里完成记一笔 → 分类 → 看列表的完整流程

---

## Phase 3 · 统计 + 日历

**目标**：能看数据趋势，知道钱花哪了

- 统计页三视图切换（日 / 月 / 年）
- 日视图：纯记录列表，无图
- 月 / 年视图：收支双柱柱状图 + 分类排行条形列表
- 收入 / 支出切换
- 日历记账视图（月历格子 + 每日收支）
- 日详情弹窗（点击日历某天）
- 分类详情页（点击分类进入）

**验收**：统计页三视图数据正确，日历可点击查看每日明细

---

## Phase 4 · 池机制（核心难点）

**目标**：虚拟预扣 / 预加 + 认领关联 —— 最有价值也最复杂

- 池管理列表（设置页池区域）
- 均摊型池：长期循环 + 自定义时间范围 + 日均虚拟记录生成
- 存池型池：押金模式，不关联天数
- 认领机制：添加记录时关联池（存入 / 取出方向）
- 状态流转：全虚拟 → 部分确认 → 已确认 / 已逾期
- 记录转均摊（长按普通记录转为池）
- 统计页虚拟 / 实际切换筛选

> ⚠️ 此阶段边界 case 多，需要大量单测覆盖

**验收**：创建均摊池 → 每日虚拟记录生成 → 实际到账认领 → 状态变更为已确认
