v3.0 回归简单记账

记账主题上线五个版本后，我们听到了最真实的声音：池太绕、钱包多余、统计看不见明细。v3.0 不新增复杂度，而是做一次「减法 + 叙事」——把记账还给「记一笔」这个动作本身，同时给钱一个名字、一张脸、一段故事。

01 · RETROSPECTIVE

v2.x 把记账做「重」了

v2.0 → v2.5 用五个版本搭完了完整的记账体系（415 条单测护航），但复杂度已经溢出用户的理解预算。下面是四个最重的地方：

PAIN 01
「池」太绕

建池表单 12 个字段（类型 / 方向 / 周期模式 / 日期范围 / 日均 / 结算方式 / 目标账户…）。用户要先理解虚拟记录、认领、周期、先付后付四个概念——这是会计学，不是记账。

PAIN 02
钱包多余

记一笔要选账户、拖行归入账户、「未归入」红标、余额迁移……对只想记一笔的用户，账户归属是二等需求。多数人心里的资产只有一个数：我总共有多少钱。

PAIN 03
统计图表优先

月 / 年视图只有柱状图 + 分类排行，想看某条具体记录必须点柱子逐级下钻到日。「翻一翻账」的高频诉求被图表挡在门外。

PAIN 04
记录没有叙事

一次云南行的 12 笔支出散落在 4 个分类、7 个日期里；一笔兼职收入混在工资中间。系统答不出「这件事总共花了多少」。而且记录没有图片，账只是数字，回忆没有画面。

02 · PRINCIPLES

三条设计原则

v3.0 的每一个取舍都用这三条裁决。

i.
三秒记一笔

主路径永远最短：金额 → 分类 → 保存。账户、图片、定期账、一程全部是「可选挂载」，收在折叠区，不挡主路。

ii.
所见即账

统计默认展示一条条真实记录，图表是「点一下才来」的附加值；总资产就是用户心里那个数，由用户亲手写下，不替用户推导。

iii.
钱要有故事

均摊的房租、压着的押金、一趟旅行、一次兼职——每一笔「整块的钱」都给它名字、封面和总账，让记账留下生活的痕迹。

03 · NAMING

两个命名决策

名字是简化的一半。「池」和「消费块」都换成用户语言。以下为首选方案 + 备选，最终由你拍板（见 09 待确认）。

需求 ① 池简化 · 改名
池 Pool→定期账
Recurring Ledger

「定期」天然传达「长期、周期性发生」，不需要理解虚拟 / 认领；「账」保持记账语境。两个子类型一并说人话：
均摊型 → 均摊（房租 / 会员 / 年薪）　存池型 → 押金

备选：长期账 · 摊销计划 · 固定账

需求 ② 消费块 · 新事物
消费块→一程
Journey

一趟旅行、一次兼职、一场演唱会，都是「一程」。它自带叙事感，贴合 App「打工浪漫」的基调，也撑得起小红书式瀑布流的封面卡片气质。支出是「花掉的一程」，收入是「赚来的一程」。

备选：账册 · 账集 · 账单故事

04 · CORE DESIGN

五项核心设计

对应你提出的 5 个需求。每一项：现状问题 → 设计方案 → 界面示意。

① 池 → 「定期账」：功能全保留，门槛砍一半

保留什么：均摊收支的核心机制（逐日生成、认领结算、逾期回滚、工资联动池）一行不动——这是 v2.3 最值钱的部分，415 条单测继续护航。

砍掉什么：把「建池」从 12 字段会计表单，变成 3 步直觉表单：

  • 第 1 步 · 选类型：三张大卡片「均摊支出 / 均摊收入 / 押金」，一句话解释，不出现「池、周期、虚拟」字眼
  • 第 2 步 · 名字 + 金额：预置常用名（房租 / 会员 / 年费 / 工资 / 押金…），点一下即填
  • 第 3 步 · 周期：默认「每月」零配置；需要才展开「自定义起止日期」

日均金额自动推导并实时预览（¥3,000 ÷ 30 天 = ¥100/天）；「手动日均、每月几号起」等收进「高级选项」折叠区。押金的 prepay/postpay 改成一个开关：「已经付了吗？」。

展示简化：卡片不再出现「虚拟 / 交易 / 周期状态」术语——均摊卡显示「¥100/天 · 本期已结 ¥2,100 / ¥3,000」，押金卡显示「待退 +¥1,500」。工资联动池（内部实现）从列表隐藏。

认领简化：沿用 v2.5-patch8 的「定期账卡片上直接结算」流程，按钮文案改为「记一笔还款 / 记一笔到账」，系统自动匹配未结清的部分，用户不接触贪心匹配细节。

② 「一程」：一件事一笔总账，一张封面，一段瀑布流

定义：一程 = 围绕「一件事」的记录集合。可以是支出（云南 7 日游），也可以是收入（设计兼职）。总金额 = 关联记录自动求和，不单独维护，永远不会对不上账。

  • 封面：每程可关联一张图片（相册选取，或复用记录已附的图），存本地 IndexedDB
  • 入口：「我的」页新增「我一程」区 → 进入瀑布流列表页
  • 瀑布流：小红书式双列，卡片 = 封面 + 标题 + 总金额；按时间排列（新在上），左右交错
  • 详情页：封面头图 + 总账 + 关联记录清单，可继续「记一笔」自动挂到本程
  • 关联方式：记账弹窗 / 编辑记录时选「所属一程」（只列同类型的程，支出程不混收入记录）
  • 删除语义：删程不删记录（仅解除关联）；删记录，程总额自动减少

无封面的程用渐变占位卡 + 大字金额，瀑布流不出现空图。

③ 取消钱包：总资产就是一个数，亲手改、随便算

移除：多账户、记账选账户、拖拽归入账户、「未归入」状态、余额迁移——全部下线。记账记录不再自动改动总资产，资产与流水彻底解耦：流水负责「钱去哪了」，总资产负责「我现在有多少」。

新的总资产：一个由用户手动维护的数字。点总资产卡 → 打开「资产计算器」：

  • 支持 ± 表达式，与记账金额输入同一套键盘逻辑：+500、-200、13000、12500+500-200 都可以
  • 实时预览「→ 调整后 ¥13,000」，不怕输错
  • 可附一句备注（「工资到账」「交完房租」），保存后写入调整历史
  • 调整历史同时是「资产趋势图」的数据源（见优化建议 ②）

迁移：升级时 Σ 现有账户余额 → 初始总资产（一次性，可见迁移提示）；旧账户数据保留只读存档，记录上的 accountId 冻结不再展示。

保留：虚拟分解 chips（待退 / 待付 / 预付未消耗 / 已赚未到账）——它们来自定期账语义，仍然有价值，只是「实际」一栏改为手动总资产。

  • 记账弹窗新增「添加图片」区：拍照 / 相册任选；已附图显示缩略图，可替换、可删除

⑤ 统计页「列表优先」：先看见账，再看图表

日 / 月 / 年三视图默认全部是「按时间排序的记录列表」，与日视图体验一致；汇总条右侧新增 「列表 | 统计」 切换，点「统计」才展示柱状图 + 分类占比。

  • 月 · 列表：按天分组，天头 = 日期 + 当日支/收小计，天头吸顶便于翻读
  • 年 · 列表：按月分组（月头 = 月份 + 当月支/收小计），月份可折叠，展开后仍按天分组
  • 统计模式：月 / 年 = 现有双柱图 + 分类排行（不动）；日视图统计 = 当日分类占比条
  • 列表行复用现有记录行组件：点击编辑、长按等交互不变；认领 / 均摊标记保留
  • 「点柱子下钻」的旧路径保留在统计模式中，两种浏览方式互不冲突

右侧手机模型可点击切换「列表 / 统计」，体验新交互。

05 · MORE IDEAS

围绕「简单记账 + 更好统计」的六个优化建议

除五项核心需求外，从记账 App 通用体验出发补充的建议。前两项强烈建议排入 v3.1；其余进 backlog 按需取用。

① 月度预算
P1 · 建议 v3.1

设一个月预算，统计页与快速记录页顶部显示进度条；花到 80% 变黄、100% 变红并轻提醒。「简单记账」最经典的闭环：记了之后，知道还能不能花。

价值 ★★★★★ · 成本 低（纯展示层 + 一个配置项）
② 资产趋势
P1 · 建议 v3.1

需求③的每次总资产修改天然生成快照——把快照画成一条趋势线放在「资产」页：这个月我的钱是变多还是变少了。手动资产从此有了时间维度。

价值 ★★★★ · 成本 极低（数据已随需求③产生）
③ 账单搜索
P2 · backlog

统计页工具条加搜索入口：按备注 / 分类名关键词过滤记录列表。列表优先之后，搜索是自然配套——翻不到就搜。

价值 ★★★★ · 成本 低
④ CSV 导出
P2 · backlog

本地导出一张 CSV（日期 / 类型 / 分类 / 金额 / 备注 / 一程）。不上云的隐私友好导出，也是需求③账户迁移前的安全网。

价值 ★★★ · 成本 极低
⑤ 智能分类建议
P3 · backlog

按时间段猜分类：早上 8 点记账默认高亮「通勤 / 早餐」，晚上 9 点高亮「宵夜 / 娱乐」。减少一次点击，但需要克制，不做成打扰。

价值 ★★★ · 成本 中
⑥ 一键「再来一笔」
P3 · backlog

长按任意记录 →「再来一笔」：同金额同分类直接记到今天。为连续小额支出（每天一杯咖啡）设计，呼应 App 的咖啡灵魂。

价值 ★★★ · 成本 极低

09 · OPEN QUESTIONS

待你确认的问题

以下决策已给出推荐项，评审时逐条拍板即可。

Q1 · 命名：「定期账」与「一程」可以吗？

备选：池 → 长期账 / 摊销计划；消费块 → 账册 / 账集。命名只影响 UI 文案层，代码内部保留 pool / journey 英文标识，改名成本极低。

Q2 · 记账与总资产彻底解耦，确认吗？

推荐：是（记录不自动改总资产，资产纯手动）。若你仍希望「记账同步影响资产」，可在 v3.1 加一个可选开关，不影响本期结构。

Q3 · 删除记录时，附图级联删除还是保留？

推荐：级联删除（无其他引用时），避免本地存储无限膨胀。若你想留作「相册」，需要额外一个图片管理页，成本上升。

Q4 · 一程封面允许从记录附图中挑选吗？

推荐：允许（旅行中拍的图直接设为封面，零额外操作）。

Q5 · 旧多账户数据迁移前，需要先导出 CSV 留底吗？

推荐：把「CSV 导出」提前到 TASK-057 之前做一个最小版（仅账户余额 + 记录表），作为迁移安全网。
